# Adachi健やかNet（AdachiHomeCareNet2026）

リポジトリ名・公開URL：`AdachiHomeCareNet2026`（旧名：在宅連携 連絡帳）

在宅で療養する患者の情報を、ケアマネジャー・薬局・訪問看護・在宅医の連携のために記録する、1ファイルのウェブアプリです。

## 公開手順（GitHub Pages）

### 0. 事前に決めること

| 項目 | 決めること |
|---|---|
| GitHubのアカウント | 個人アカウントか、組織（Organization）アカウントか。組織アカウントにすると、担当者が替わっても引き継げます |
| リポジトリ名 | **`AdachiHomeCareNet2026`**（URLの一部になる。大文字・小文字を含めてこのとおりに入力） |
| 公開範囲 | 無料プランでは GitHub Pages は公開リポジトリでのみ使えます。非公開リポジトリから公開するには Pro・Team・Enterprise が必要です。どのプランでも、公開されたサイトはインターネットから見られます（アクセスを組織内に限定するには GitHub Enterprise Cloud が必要）。このアプリ本体には患者データが入っていないため、公開リポジトリで運用できます |
| 管理者 | リポジトリを更新できる人（2人以上を推奨） |

### 1. リポジトリを作る

1. GitHub にログインし、右上の「＋」→「New repository」を選ぶ。
2. Repository name に `AdachiHomeCareNet2026` と入れる。
3. 公開範囲は「Public」を選ぶ（無料プランの場合）。
4. 「Add a README file」はチェックしない（このREADME.mdをアップロードするため）。
5. 「Create repository」を押す。

### 2. ファイルを置く

1. 作ったリポジトリの画面で「uploading an existing file」（または「Add file」→「Upload files」）を選ぶ。
2. `index.html` と `README.md` をドラッグして入れ、「Commit changes」を押す。
3. `.gitignore` は隠しファイルのためドラッグで入らないことがあります。その場合は「Add file」→「Create new file」で、ファイル名に `.gitignore` と入れ、中身を貼り付けて「Commit changes」を押す。
4. リポジトリの一覧に `index.html`・`README.md`・`.gitignore` の3つがあることを確認する。**患者データや書き出したファイルが入っていないこと**も確認する。

### 3. GitHub Pages を有効にする

1. リポジトリの「Settings」→ 左のメニューの「Pages」を開く。
2. 「Build and deployment」の Source を「Deploy from a branch」にする。
3. Branch を「main」、フォルダを「/(root)」にして「Save」を押す。
4. 数分待ってから「Pages」の画面を開き直すと、上部に公開URLが表示される。

公開URLの形式（独自ドメインを使わない場合）：

```
https://<アカウント名または組織名>.github.io/AdachiHomeCareNet2026/
```

- プログラムのファイル名は `index.html` のままにします。この名前のファイルが、上のURLを開いたときに自動で表示されます（ファイル名を `AdachiHomeCareNet2026.html` に変えると、URLの末尾に `AdachiHomeCareNet2026.html` を付けないと開けなくなります）。
- URLの `AdachiHomeCareNet2026` の部分は、大文字・小文字をリポジトリ名と同じにして案内してください。

5. 「Enforce HTTPS」にチェックが入っていることを確認する（フォルダへの保存機能は https でないと動きません）。

### 4. 公開できたかを確かめる

1. パソコンの Chrome または Edge で公開URLを開く。
2. 「Adachi健やかNet：はじめに管理者を登録」の画面が出ることを確認する。
3. 右上の「保存先フォルダ」を押して、OneDrive（またはGoogleドライブ）の連絡帳用フォルダを選べることを確認する。
4. 管理者を2人登録する（1人目を登録後、管理画面の「メンバーと権限」で2人目を代理登録）。
5. 共有フォルダに `members/`・`settings.json` などができていることを確認する。

### 5. メンバーに知らせること

- アプリのURL（ブックマークを依頼。QRコードにしてもよい）
- 共有フォルダ（OneDriveは「マイファイルにショートカットを追加」、Googleドライブは「マイドライブにショートカットを追加」して、パソコンに同期）
- 使う手順：URLを開く →「保存先フォルダ」で共有フォルダを選ぶ → ログイン画面で自分のプロファイルを登録 → 担当患者のチームに加えてもらう
- 問い合わせ先（管理者の氏名・連絡先）

**URLは1つに統一してください。** ブラウザ内の作業データとフォルダの接続設定はURL（ドメイン）ごとに別々に保存されるため、途中でURLを変えると全員がフォルダを選び直す必要があります（共有フォルダのデータは失われません）。

### 6. アプリを更新するとき

1. リポジトリの `index.html` を開き、「Add file」→「Upload files」で新しい `index.html` をアップロードして上書きする（または鉛筆マークで編集）。
2. 「Commit changes」を押す。コミットのメッセージに変更内容を書く（例：「FHIR書き出しを追加」）。
3. 数分後に公開サイトへ反映される。メンバーには「画面を再読み込み（Ctrl＋F5）してください」と伝える。
4. 患者データは共有フォルダにあるため、更新で消えることはありません。
5. 以前の版に戻すときは、リポジトリの「History」から前のコミットの `index.html` を取り出して上書きする。

### 7. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| URLを開くと 404 になる | Pages の設定（main・/(root)）、ファイル名が `index.html`（小文字）か、公開から数分たったか |
| 「保存先フォルダ」が使えない | パソコンの Chrome・Edge で開いているか、URL が https か |
| 古い画面のまま | Ctrl＋F5 で再読み込み。ブラウザのキャッシュが残っていることがある |
| ほかの人の記録が見えない | 同じ共有フォルダを選んでいるか、その患者のチームに入っているか、同期アプリが動いているか |

## データの置き場所と、共有フォルダの権限の限定

### 基本の設計

| 置き場所 | 置くもの |
|---|---|
| **Git（GitHub）** | プログラムだけ（`index.html`・`README.md`・`.gitignore`）。患者データ・メンバー情報・ログは一切置かない |
| **OneDrive または Googleドライブの共有フォルダ** | すべてのデータ（患者・連絡帳・評価・Todo・資料と写真・メンバー・カンファレンス・操作ログ・設定） |
| **各パソコンのブラウザ** | 作業用の一時的な写し。ログアウトすると、患者に関する写しは消去される（メンバー一覧と保存先フォルダの接続情報だけ残る） |

- 保存先フォルダに接続しないと、ログインもデータの閲覧もできません（ブラウザだけに保存する使い方はありません）。
- 起動するとまず「データの保存先に接続」画面が出ます。2回目以降は「保存先フォルダに再接続」を押すだけです。

### 共有フォルダの準備（管理者）

1. **組織アカウント**（Microsoft 365 の職場アカウント、または Google Workspace）で用意する。個人向けの無料アカウントは、管理機関の統制が効かないため使わない。
2. 共有フォルダは**管理者2人以上が所有・管理できる場所**に作る（例：Microsoft 365 なら Teams・SharePoint の専用ライブラリ、Google Workspace なら共有ドライブ）。1人の個人の OneDrive に作ると、その人が異動・退職したときにデータが失われるおそれがある。
3. フォルダ名は患者名などを含まない名前にする（例：`AdachiHomeCareNet2026_data`）。
4. 空のフォルダを作ったら、管理者がアプリで「保存先フォルダを選ぶ」→ 最初の管理者を登録 → 2人目の管理者を代理登録する。

### 権限の限定（必須）

| 守ること | 内容 |
|---|---|
| **共有相手は「特定のユーザー」だけ** | 共有リンクの範囲は、名前・メールアドレスで指定した人だけにする。「リンクを知っているすべてのユーザー」「組織内のユーザー（全職員）」のリンクは作らない。Googleドライブでは「一般的なアクセス」を「制限付き」にする |
| **アプリのメンバーと一致させる** | フォルダを共有した人＝アプリに登録したメンバー、にそろえる。フォルダにアクセスできる人は、アプリの担当設定に関係なくファイルを直接読めるため |
| **権限の種類** | アプリが書き込むため、メンバーには「編集」権限が必要。削除や構成変更は管理者だけが行う運用にする（Googleの共有ドライブでは、メンバーの役割を必要最小限にする） |
| **外部共有** | 他の事業所の人を加えるときは、所属機関の外部共有の規程に従う（多くの機関では管理者の承認が必要） |
| **離脱したら外す** | アプリで「離脱」したメンバーや利用停止にしたメンバーは、**フォルダの共有からも外す**（アプリ側からフォルダの権限は変えられない） |
| **定期的に見直す** | 月1回など決まった時期に、フォルダの「アクセス許可の管理」（Googleは「共有」画面）で共有相手の一覧を確認し、アプリのメンバー一覧と照合する |
| **端末** | 共有フォルダを同期するパソコンは、所属機関が管理する端末に限る。共用パソコンでは、使い終わったら必ずログアウトする |

### 限界（重要）

- アプリの閲覧制限（担当登録・ログイン・管理画面）は、画面の上での取り決めです。**実際のアクセス制御は、共有フォルダの権限設定だけが担っています。**
- 共有フォルダのファイルは暗号化していません。保護は OneDrive・Googleドライブ側の組織の設定（多要素認証、条件付きアクセス、外部共有の制限、秘密度ラベルなど）に依存します。設定内容は所属機関の情報システム部門に確認してください。
- 本格運用の段階では、組織アカウントでの認証とサーバー側のアクセス管理を備えた仕組みが必要です。

## 使い方

### 入口は一つ：ログインと権限

- だれでも同じ「ログイン」画面から、氏名とログインパスワードで入ります。初回は最初の管理者を登録します（ログインパスワードと、別の管理者パスワードを設定）。
- はじめて使う人はログイン画面で自分のプロファイルを登録します。権限は登録後に管理者が付けます。
- 権限は各メンバーのプロファイルの属性です（管理／カンファレンス管理者／利用停止）。

### 管理画面（二つ目のパスワードで開く）

- 管理の権限がある人だけ、上部に「管理」が出ます。ログインとは別の管理者パスワードで開き、15分操作がないと自動で閉じます。
- 管理画面のタブ：
  - メンバーと権限：個人プロファイルの書き換え、権限の付与・解除、利用停止、ログインパスワードの再設定、管理者パスワードの設定
  - 患者とチーム：全患者とチーム（現況）の一覧、チーム未登録の患者の確認
  - 操作ログ：だれが・いつ・何をしたかの一覧（メンバー・操作・期間・患者名で絞り込み、CSV書き出し）
  - データ（保存・取込）：全データの書き出し・読み込み、HL7 FHIR の取り込み
- 管理画面を開いている間は、全患者を閲覧・操作できます。

### 操作ログ

ログイン・ログアウト、管理画面の開閉、患者の閲覧、連絡の既読、登録・更新・削除、権限の変更、書き出し・読み込み、FHIR取込、カンファレンスの開始・終了を記録します。保存先フォルダの `logs/年-月/メンバーID.json` にメンバーごと・月ごとに保存します（同時に書き込んでも衝突しにくい形）。改ざんを防ぐ仕組みではありません。

### 管理者は2人以上

- 管理者が1人のときは、管理の権限を持つ人の画面上部に「管理者が1人です」と警告が出ます。
- 管理者が2人以下のときは、管理者の権限を外したり利用停止にしたりできません（常に2人以上を保つため）。
- 管理画面の「メンバーと権限」で、メンバーを**代理登録**できます（仮のログインパスワード・仮の管理者パスワード）。仮のパスワードは、本人が最初に使うときに変更を求めます。

### HL7 FHIR（試行）

**入口**：管理画面の「データ」（取り込み先の患者を選ぶ／新規登録）と、各患者のプロファイルの「外部データ（HL7 FHIR 取込）」の2か所。

**手書きの欄は上書きしません。** 取り込んだ内容はプロファイルの「外部データ」に別に保存し、必要な行にチェックして「手書き欄へ追記」します。空欄の基本情報（ふりがな・生年月日・性別・住所・電話）だけは補います。手書き欄の入力・上書き・追記・補完はすべて「変更履歴」に残り、各欄の見出しの横に最終変更の日付と変更者が出ます（上書きは変更前の内容も残ります）。

| FHIR R4 のリソース | 取り込み先 | 保持するコード |
|---|---|---|
| Patient | 基本情報（空欄のみ補完） | ― |
| Condition | 外部データの傷病名 | 病名交換用コード（標準病名マスター）、ICD-10 |
| MedicationRequest／MedicationStatement（Medication） | 外部データの処方 | YJコード、HOTコード |
| AllergyIntolerance | 外部データのアレルギー | ― |
| Practitioner・PractitionerRole・Organization・CareTeam | 「チーム」タブの外部ケアチーム情報（氏名が一致するメンバーをチームに加えられる） | ― |
| Composition・DocumentReference | 連絡帳（診療情報提供書・退院時サマリーを判別）と資料（添付のPDFなど） | LOINC 57133-1・18842-5 で判別 |
| Observation | 日々の評価（体重・体温・血圧・脈拍・SpO2） | LOINC |

コード体系は system の URI で判定し、URI がない場合は桁数から推定します（推定は「（推定）」と表示）。HOT9 は `urn:oid:1.2.392.200119.4.403.1` など JP Core の NamingSystem に載る URI を判定に使っています。YJコードの URI（`urn:oid:1.2.392.100495.20.2.73`）は原文で確認していません。

**書き出し**：患者のプロファイル、または管理画面の「データ」から、FHIR R4 の Bundle（collection）として書き出します。Patient・Practitioner・CareTeam・Condition・MedicationStatement・Communication（連絡帳）・Task（Todo：あて先ごと、期限・状態つき）・Observation を含みます。JP Core・JP-CLINS のプロファイル検証は行っていません。

### 担当（チーム）と閲覧

- 各患者には担当メンバー（チーム）を登録します。項目は、患者での役割・担当日・離脱日・現況（介入中／依頼中（開始前）／一時中断（入院など）／終了）です。
- 担当でない患者は記録が表示されず、「担当として登録」を求められます。患者一覧（トップ）には自分の担当患者だけが出ます。
- 患者の画面の上には「足跡」（誰がいつ見たか）が出ます。「チーム」タブで各メンバーの最終閲覧日時を確認できます。

### 連絡帳・既読・Todo

- 連絡を開くと既読になります。連絡ごとに「既読 n/チーム人数」と既読者・未読者が表示され、一覧では未読が太字になります。
- 連絡を書くときに「やること」とあて先（個人・複数・チーム全員）を選ぶと、Todoになります。あて先を選ばなければ自分あてです。既存の連絡からもTodoを出せます。
- 「Todo」画面には、自分あての未完了・自分が依頼したもの（進み具合）・完了済みが並びます。患者ごとの「Todo」タブでも追加・確認できます。

### マイページ

- 自分のプロファイルの編集と、担当患者の一覧（役割・担当日・離脱日・現況・最終閲覧）。現況の変更と「今日で離脱」ができます。

### カンファレンス

- カンファレンス管理者（または管理者）がカンファレンスを作り、供覧する患者を選んで「開始」します。氏名をイニシャルにする設定ができます。
- 開催中は全メンバーの画面に案内が出て、担当でない患者も「症例供覧」の画面で閲覧できます（足跡に「カンファ」と残ります）。終了すると閲覧できなくなります。

### そのほか

- プロファイル・日々の評価・医療材料・統計・資料と写真は、これまでどおりです。統計と医療材料の一覧は、見られる患者（担当患者、管理者は全員）だけを対象にします。

## 閲覧制限についての重要な注意

ログインと担当登録による閲覧制限は、**画面の上での取り決め**です。共有フォルダのファイルや、このブラウザの保存領域そのものは暗号化されておらず、フォルダを共有した人なら中身を読めます。利用者ごとの厳密なアクセス制御や監査証跡が必要な場合は、認証（組織アカウント）とサーバー側のアクセス管理を備えたシステムを使ってください。

## データの保存場所と共有

### 保存先フォルダ（推奨）

起動時の「データの保存先に接続」画面（または右上の「保存先フォルダ」）で、OneDrive・Googleドライブなどの**同期フォルダの中**に作った専用フォルダを選びます。データはすべてそのフォルダにファイルとして保存されます。

```
選んだフォルダ/
  renkei-techo.json            … このフォルダが連絡帳用であることの印
  patients/<患者ID>.json        … 患者1名分（プロファイル・連絡帳・日々の評価・資料の一覧）
  attachments/<患者ID>/...      … PDF・写真の実ファイル
```

- 同じフォルダを共有した人が、それぞれのパソコンで同じフォルダを選ぶと、同じデータを読み書きできます（同期はOneDrive・Googleドライブのアプリが行います）。
- 保存のたびにフォルダ内の最新のファイルを読み、連絡・評価・資料を1件ずつ新しい方で統合してから書き込みます。削除した記録も記録として残し、他の人の保存で復活しないようにしています。
- 画面に戻ったとき（未入力の作業がない場合）と「フォルダから更新」を押したときに、フォルダの内容を読み直します。
- 対応ブラウザ：パソコンの Chrome・Edge（File System Access API）。スマートフォンや Safari・Firefox では使えないため、「書き出す」「読み込む」を使います。

### 書き出す・読み込む

「書き出す」でパスワード付きの暗号化ファイル（`.rtc`、AES-GCM 256bit・PBKDF2）を作れます。バックアップや、フォルダを共有できない相手への受け渡しに使います。

### 注意

- 2人がほぼ同時に同じ患者を保存し、同期が間に合わないと、OneDrive・Googleドライブが「競合したコピー」を作ることがあります。その場合は新しい方を残し、もう一方を「読み込む」で取り込んでください。
- 共有フォルダは、所属機関が認めた組織アカウントの範囲だけで共有してください。

## リポジトリに置いてよいもの・いけないもの

- 置いてよい：`index.html`、`README.md`（プログラムのみ）
- 置いてはいけない：患者データ、書き出したファイル（`.json`、`.rtc`）、資料や写真

`.gitignore` に次を入れておくことを勧めます。

```
*.json
*.rtc
data/
```

## 注意
